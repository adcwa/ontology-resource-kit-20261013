# 下载后如何使用：先核实文件，再加载语义

这个资料目录没有把所有资源混称为“OWL 本体”。OWL/RDF 是语言或表示层；SKOS 等是词汇；RAMI 是参考架构；FHIR、IFC、DTDL、GTFS 等各有不同的信息模型与交换用途。每项的入口、类型和需要确认的范围已写入目录。分类是整理用途，不是替发布方做符合性认证。

## 先看文件身份

检查下载报告中的原始 URL、实际重定向、获取时间、内容类型、GitHub commit（适用时）和 SHA-256。浮动地址与默认分支快照不一定是稳定发行版本。下载失败后得到的 HTML 错误页面，不能通过更改扩展名变成 OWL。

ISO 标准说明页不是标准正文；GitHub 社区转换仓库不是标准机构对其完整性的背书；本体文件也不是数据实例全集。目录保留“原始条目”和“修正后的入口”，避免纠错过程中丢失来源。

## Protégé 与离线 imports

1. 先打开一个明确的 `.owl` / `.rdf` / `.ttl` 本体文件，而不是直接把全部仓库或 HTML 拖入。
2. 查看本体 IRI、版本 IRI 和 `owl:imports`。文件成功解析不代表 imports 均已加载。
3. 为需要离线使用的依赖保留匹配版本，再配置本地 catalog 映射。目录工具未自动计算整个 imports 闭包。
4. 在明确需要的模块集合上做语法、Profile、逻辑一致性与用例测试；不要在首次打开时把不同顶层本体强行全部导入一个工程。

以上是操作检查清单，不保证任何具体版本已经通过测试。此包没有运行 Protégé 或 OWL 推理器，也未认证任何源库的语义质量。

## 不应自动做的转换

不要为了统一格式，把 SUMO、一阶逻辑文档、XML 交换规范或 JSON 模型简单改后缀为 `.ttl`。转换需要明确的映射、表达能力边界、版本和测试；一个转换结果不自动等于原规范全部语义。

不要因为两个资源都有“设备”“部件”“过程”等词，就直接声明 `owl:equivalentClass`。本次归并只合并重复入口，不建立跨本体的语义等价关系。

## 私有使用与共享

每次准备把下载资料传入团队知识库、公开仓库、客户交付物或模型训练集之前，单独核查对应版本的许可、版权与账户授权范围。下载成功和可公开浏览都不自动等于可以再分发。
